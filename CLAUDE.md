# TripDesk

Learning and portfolio project: a corporate business-travel hotel booking platform, built by one
developer with AI assistance, using spec-driven development with Spec Kit. Not a production system.

The project principles live in `.specify/memory/constitution.md`. Read it before planning or
implementing anything; it takes precedence over this file.

## Working rules

1. **Stay in scope.** Do only what the request asks. Put any other idea under a "Suggestions"
   heading at the end of your reply. Do not apply it.
2. **No silent gap-filling.** When a requirement is unclear, ask, or state the assumption
   explicitly in the plan or your reply. Never decide quietly in code or docs.
3. **Edit, don't regenerate.** When updating a spec, plan or other existing document, change only
   the sections named in the request. Do not rewrite or reorder the rest.
4. **Report every change.** After editing, list each file you changed and summarize what changed
   in it.
5. **Decisions belong to the owner.** When there are real alternatives (libraries, API shape, UX
   behavior), present them with a recommendation and wait for a decision.
6. **No new dependencies** unless the plan lists them and the owner has approved them.
7. **Verify, don't invent.** Do not use APIs, library options or configuration keys you are not sure
   exist. Say so and check the official documentation instead.
